# 04-A 로컬 회차 제어 리뷰

기준: cdea2fb 이후 제품 변경과 신규 파일. work/local-session-control. 조정자와 독립 두 축 리뷰, 구현자는 지정 대체 Codex.

## 명세 축

- 준비 요청 식별자가 base64url 첫 문자 -/_를 생성하지만 서버는 첫 영숫자만 허용한다. 약1/32 확률로400이고 실패한 키를 유지하므로 같은 화면 재시도가 반복 실패한다.
- 액션 이전의 지연된 조회가 준비/취소 성공 후 최신 상태를 덮어쓴다. 진행 중 조회가 있으면 액션 후 갱신도 생략된다. 이전 응답 무효화와 순서 제어 검사가 필요하다.

## 표준 축

- 요청 식별자 형식 불일치를 독립적으로 확인했다.
- 다른 로그인 family의 grant 갱신이 방송 행을 잠근 뒤 회차를 기다리고, 원래 family 로그아웃은 회차를 잠근 뒤 outbox 외래키의 방송 잠금을 기다릴 수 있다. 실제 PostgreSQL 재현 및 잠금 순서 수정이 필요하다.

## 상태

두 축 각2건(중복 제외3건)을 구현자에게 반환했다. 검토는 읽기 전용이며 잠금 순환의 실제 재현은 수정 단계에서 확인한다. 실제 송출·LIVE·휴대폰·외부망은 이번04-A 범위가 아니다. 수정 후 재검토 전 완료로 표시하지 않는다.

## 수정 후 재리뷰

원래 3건은 해결됐다. PostgreSQL의 outbox INSERT 시점에 지연을 주어 잘못된 family 갱신과 로그아웃의 교착을 재현했고, 방송 잠금 전 family 거절로 수정했다. 키는 영문 접두사로 시작하며 이전 응답은 epoch로 배제한다.

표준 축 잔여 확정 결함 0건. 명세 축은 무효화된 과거 조회가 완료되지 않으면 `_fetchingCount`가 남아 새 주기 조회·수동 새로고침을 차단하는 잔여 결함 1건을 반환했다. 최종 수정·재검토 대기.

## 최종 재리뷰

무효화된 요청도 busy로 계산하던 문제는 최신 요청 epoch만 추적하도록 수정했다. 이전 응답과 finally는 현재 요청 상태에 영향을 주지 않는다. 명세 축 최종 잔여 확정 결함 0건, 표준 축 잔여 확정 결함 0건이다. 미완료된 이전 응답을 유지한 채 준비/취소 후 다음 polling이 종료 상태를 반영하는 회귀도 확인했다.
