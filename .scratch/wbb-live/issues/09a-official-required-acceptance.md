# 09-A: 공식 필수 기능의 공개 인수

**Status:** ready-for-agent (로컬 평가 로그인·최종 회귀; 공개 물리 기기 인수는 환경 대기)
**Blocked by:** 07-A2 제품 종료 완료 통합(로컬 지원 범위 충족). 실제 iPhone과 Labtop 외부 접속 환경은 별도 인수 관문이다.
**목표:** 공모 필수 항목을 공개 HTTPS 서비스와 두 물리 기기에서 재현하고 README만으로 평가자가 같은 절차를 실행하게 한다.

## 진행 경계

1. 07-A2가 제품에 연결된 뒤, 기존 로컬 서비스와 분리한 전용 스택에서 최종 제품을 clean bootstrap한다. 이 단계에서는 공개 DNS·Caddy·기존 볼륨을 변경하지 않는다. API/worker/패치 MediaMTX에 동일한 완료 계약 root·slot·key를 주입하고, 새 이력 볼륨을 명시적으로 초기화한다.
2. 위 스택으로 아래 전체 필수 기능과 서버 재시작을 검증한다. 합성 카메라·음원 검사는 자동 회귀 근거이고 실제 휴대폰 인수로 기록하지 않는다.
3. 공개 구성은 별도의 배포 산출물과 사전 점검 결과로 준비한다. 사용자가 접근 가능한 Labtop·실제 iPhone·외부망 환경을 제공하면 기존 서비스에 영향 없는 범위에서 배포하고 실제 두 기기 인수를 수행한다. 환경 부재 동안 이 티켓을 `done`으로 올리지 않는다.

평가 로그인 방식은 공개 저장소에 실제 암호를 싣지 않는 **서버에서 명시적으로 켜는 평가용 바로 로그인**을 우선한다. 전용 평가 계정으로만 세션을 발급하고 일반 계정과 구분하며, 기존 Origin·rate limit·방송 소유자 검사를 그대로 적용한다. 활성화 여부와 제한은 환경변수로 설정하고, 비활성 상태에서는 버튼과 서버 경로가 모두 동작하지 않아야 한다. 실제 평가 로그인은 공개 HTTPS에서 별도로 확인한다.

### 평가 로그인 구현 계약 초안

- 운영자가 전용 평가 계정을 기존 가입 경로로 미리 만들고, 그 계정의 이메일·암호를 Git에 없는 배포 Secret으로만 제공한다. 세 값 `WBB_EVAL_LOGIN_ENABLED`, `WBB_EVAL_LOGIN_EMAIL`, `WBB_EVAL_LOGIN_PASSWORD`는 모두 일치하게 구성한다. 기본은 비활성이고 부분 설정은 시작 실패다. 실제 암호는 로그·HTTP·README에 노출하지 않는다.
- `POST /api/v1/auth/evaluation-login`은 정확한 Origin과 전용 IP·평가 계정 rate limit을 거친 뒤 기존 `auth.Login`으로 그 한 계정의 정상 JWT·서버 세션·HttpOnly refresh cookie를 발급한다. 계정이 없거나 암호가 맞지 않으면 fail-closed로 처리한다. 로그인 후 CRUD·송출은 기존 소유자 권한을 그대로 통과하며 다른 사용자의 방송 제어는 거절한다. 비활성일 때는 세션을 절대 발급하지 않는다.
- `GET /api/v1/auth/providers`의 `evaluationEnabled`를 Flutter가 읽어 로그인 화면 버튼을 표시한다. 버튼은 일반 인증 상태 갱신과 로그아웃·만료 처리를 재사용하며, 비활성 및 서버 오류에는 감춘다. 토큰은 기존처럼 브라우저 메모리에만 둔다.
- 공개 HTTP+실제 DB의 비활성/부분 설정/정상 로그인/잘못된 Origin/rate limit/로그아웃/소유자·타 사용자 권한과 Flutter 버튼 동작을 검증한다. 이후 실제 공개 HTTPS에서 버튼을 눌러야 공식 평가 로그인 인수로 기록한다.

## 구현 범위

1. 현재 검증된 단일 품질 PC 화면·공유 소리+마이크, 휴대폰 카메라+마이크, 익명 목록·상세·시청, 이메일 인증·방송 CRUD·소유자 권한 및 정확한 종료를 공개 서비스에 연결한다. ABR·댓글·도네이션·녹화와 대규모 부하는 이 필수 인수의 완료 조건이 아니다.
2. WBB 전용 k3s namespace·데이터 볼륨·비밀 주입, Caddy `live.wombatburrow.com` HTTPS, 브라우저가 접근할 WHIP ICE UDP/TCP 경로를 구성한다. 기존 서비스·데이터는 유지하고 DB·Redis·Kafka·MediaMTX 관리 API를 외부에 열지 않는다. 외부 변경은 실제 접근 가능성과 사용자 지시를 확인한 뒤 실행한다.
3. 평가 로그인은 운영에서 별도 안전하게 준비한 계정 또는 평가용 바로 로그인 기능 중 하나를 실제로 제공한다. 평가용 바로 로그인이라면 서버에서 명시적으로 활성화하고 제한·남용 방지·일반 계정과의 분리를 검증한다. 실제 비밀번호·토큰은 Git·문서·로그에 넣지 않는다. README에는 서비스 URL, 실제 작동하는 평가 로그인 방법, 환경변수 자리표시자, clean checkout 실행, PC/모바일 송출·시청·종료 절차, 확인된 브라우저·기기와 한계를 기록한다.
4. 외부 접속 전에 로컬 전용 환경에서 최종 제품의 가입·로그인·로그아웃, CRUD, 비로그인 조회·시청, 소유자/타 사용자/비로그인 권한, PC 두 음원, 모바일 카메라·마이크, 종료·재시작 영속성을 공개 HTTP 및 Flutter UI로 검증한다.

## 인수 기준

- 실제 PC Chrome/Edge의 탭 공유 소리와 마이크를 별도 물리 기기에서 구분해 듣고 화면 변화를 본다. 방송 시작·공유 중지·종료 뒤 기존 미디어 연결/URL이 종료되는지 확인한다.
- 실제 iPhone Chrome에서 카메라·마이크를 송출하고 다른 물리 기기에서 영상·음성을 본다. 시작·종료 및 권한 거절을 확인한다. 모바일 화면 잠금·백그라운드 지속은 지원으로 추정하지 않는다.
- 모바일 회선 등 외부망에서 공개 HTTPS URL에 접속해 익명 시청과 평가 로그인을 수행한다. 브라우저 신호 연결뿐 아니라 실제 RTP 수신·HLS 재생을 확인한다.
- API/DB 재시작 후 방송 제목·설명·종료 상태를 다시 조회한다. 보호 API의 비로그인·타 사용자 거절과 소유자 허용을 서버 응답으로 확인한다.
- 공개 저장소 clean checkout의 빌드·테스트·실행 절차를 재현하고 비밀·개인 로컬 경로·잘못된 서비스 주소가 게시물에 없는지 검사한다.

실제 기기나 외부 접속이 불가능한 동안은 로컬 구현·자동 검사만 기록하고 공식 인수를 통과로 표시하지 않는다. 프로젝트의 03 ABR, 07-B Kafka inbox, 08 관측성 및 09 운영 규모 목표는 별도 티켓으로 계속 추적한다.

검사 항목과 물리 기기 관측란은 `docs/verification/09a-official-required-acceptance.md`에서 관리한다.
