# 필수 기능 인수 기준

상태: 모두 미실행. 테스트 계획이며 구현 완료 또는 실제 기기 검증의 증거가 아니다.
공모 요구사항 ID는 `01-contest-requirements.md`를 따른다.

## 공통 준비

- 방송자 A, 다른 사용자 B, 비로그인 브라우저를 구분한다.
- PC와 실제 휴대폰을 준비하고 송출 기기와 시청 기기를 분리한다.
- 운영체제·브라우저 버전·네트워크·실행 일시·결과·관련 로그를 남긴다.
- 서비스는 실제 기기에서 접근 가능한 HTTPS 환경에서 검사한다.
- 아래 오류·복구 검사는 필수 요구사항의 완결성을 확인하기 위한 내부 품질 기준이다.

| 검사 | 절차 및 기대 결과 | 대응 ID |
| --- | --- | --- |
| PC 송출 | A가 로그인→방송 등록→화면/탭 선택→마이크와 공유 오디오 허용→시작. 다른 기기의 비로그인 시청자가 화면 변화와 마이크·탭/시스템 소리를 모두 확인한다 | PC-01~04, BCAST-02, AUTH-02 |
| PC 종료 | 종료 버튼 또는 브라우저 공유 중지 사용 시 로컬 캡처와 서버 미디어 연결이 정리되고 다른 기기에도 종료가 반영된다 | PC-04, BCAST-03 |
| 모바일 송출 | 실제 휴대폰에서 A 로그인→카메라·마이크 허용→시작. 다른 기기의 비로그인 시청자가 카메라 영상과 음성을 확인한다 | MOB-01~03, BCAST-02 |
| 모바일 종료 | 휴대폰에서 종료하면 카메라·마이크 캡처와 송출이 정리되고 시청자는 종료 상태를 확인한다 | MOB-03, BCAST-03 |
| 목록·상세·CRUD | A가 등록한 방송을 목록과 상세에서 확인하고 수정한 제목이 반영되며 삭제 후 일반 조회에서 제외된다 | BCAST-01~02 |
| 영속성 | 방송 등록·수정·종료 후 API 서버와 DB 컨테이너를 볼륨 유지 상태로 재시작한다. ID·소유자·제목·종료 기록을 재조회한다 | BCAST-04 |
| 인증 | 가입·중복 가입·정상/실패 로그인·새로고침 후 상태·로그아웃을 검사한다. 로그아웃한 인증 수단으로 보호 API를 다시 호출하면 거절된다 | AUTH-01 |
| 권한 | 아래 권한표를 UI와 직접 API 호출로 검사한다. 클라이언트 ownerId 변조로 소유권을 취득할 수 없다 | AUTH-02~03 |
| 미디어 권한 | 시청용 토큰으로 영상/음성 발행을 시도하면 거절된다. 다른 방송의 송출 토큰을 요청하거나 종료된 송출 권한을 재사용할 수 없다 | AUTH-03, BCAST-03 |
| 중복·경합 | 방송 시작/종료를 반복 클릭하고 두 탭에서 동시에 제어해도 송출자가 중복 생성되거나 종료 상태가 LIVE로 되돌아가지 않는다 | PC-04, MOB-03, BCAST-03 |
| 실패·연결 끊김 | 권한 거부, 공유 취소, 오디오 트랙 없음, 네트워크 단절, 송출 탭 닫힘을 검사한다. 오류 안내와 리소스 정리를 확인하고 잘못된 LIVE 상태를 복구한다 | PC-02, MOB-01, BCAST-03 |
| 빌드·실행 | 문서화한 절차로 깨끗한 환경에서 빌드·실행하고 환경변수 누락 시 원인을 확인할 수 있다 | BASE-01, README |

## 서버 권한표

| 기능 | 비로그인 | 방송 소유자 A | 다른 로그인 사용자 B |
| --- | --- | --- | --- |
| 목록·상세·방송 시청 | 허용 | 허용 | 허용 |
| 방송 등록 | 401 | 허용, 자신을 소유자로 지정 | 허용, 자신을 소유자로 지정 |
| A 방송 수정·삭제 | 401 | 허용, 상태 정책 적용 | 403 |
| A 방송 시작·종료·송출 토큰 발급 | 401 | 허용, 상태 정책 적용 | 403 |
| 시청용 연결 정보 발급 | 허용, 수신 전용 | 허용, 수신 전용 | 허용, 수신 전용 |

존재하지 않는 방송은 404, 현재 상태와 충돌하는 요청은 409를 기본 설계 후보로 한다. 공개 API 계약에서 최종 고정한다.

## 제출 전 확인

- 실제 서비스 URL에서 위 필수 시나리오를 재실행한다.
- 평가용 로그인 수단을 제공하되 운영 비밀이나 개인 비밀번호를 저장소에 넣지 않는다. 데모 로그인 방식과 권한 제한은 설계에서 확정한다.
- README에 정확히 검증한 지원 환경, 소리 공유 선택 방법, 송출·시청·종료 절차를 적는다.
- 공개 저장소에 소스, 실행 절차, 환경변수 예시, 오픈소스 출처가 포함되는지 확인한다.
- 실제 결제, 댓글, 녹화는 필수 시나리오가 통과한 뒤 별도 범위로 다룬다. 선택 기능의 결제는 테스트 모드만 사용한다.
