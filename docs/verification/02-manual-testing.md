# 티켓02 수동 테스트 방법

이 문서는 검사 절차다. 실제 PC·휴대폰 인수 검사의 성공 기록이 아니다. 현재 실험은 제품 Flutter UI나 로그인 기능과 연결되지 않았다. 여러 송출/자동 검사를 같은 source 경로에서 동시에 실행하지 않는다.

## 로컬 CPU 검증 화면 준비

다른 WBB 미디어 검사나 SSH 포워딩이 같은 포트를 사용하지 않을 때 실행한다.

```sh
cd experiments/media-single-rendition
./start.sh
```

Chrome에서 `http://127.0.0.1:8090`을 연다. 서버가 계속 실행되는 터미널 환경에서 사용한다. 다른 포트 점유가 보고되면 그 프로세스를 무조건 종료하지 말고 현재 검사가 끝날 때까지 기다린다.

GPU 실험은 별도 서버·SSH 포워딩 구성을 사용한다. [VAAPI 실험](../../experiments/media-vaapi/README.md)의 준비 절차가 끝난 뒤 같은 로컬 웹 화면을 사용한다. CPU start.sh와 GPU 포워딩을 동시에 기동하지 않는다.

## 1. 합성 송출로 환경 확인

1. `합성 모드 시작`을 누른다. 실제 카메라·마이크·화면을 사용하지 않는다.
2. WHIP 송출 성공과 `ICE: connected`를 확인한다.
3. 다른 Chrome 창에서 같은 주소를 열고 `재생`, `소리 켜기`를 누른다.
4. 움직이는 합성 화면·변하는 시각과 톤이 전달되는지 확인한다.
5. 송출 창의 `송출 정지`를 누른다. 새 영상·음성은 더 이상 생성되지 않아야 한다. 수신기에 이미 쌓인 버퍼가 잠시 재생되는 것과 새 송출을 구분한다.

## 2. PC 화면·탭 소리·마이크

이어폰을 사용해 재생 소리가 마이크로 다시 들어가는 현상을 피한다.

1. 소리가 나는 테스트 탭을 준비한다. 개인정보가 없는 화면을 선택한다.
2. 송출 창에서 `PC: 화면+탭소리+마이크`를 누른다.
3. Chrome 공유 선택창에서 테스트 **탭**과 `탭 오디오 공유`를 선택한다. 전체 화면/시스템 오디오 지원은 OS·브라우저별로 다르며 확인하지 않은 조합을 통과로 기록하지 않는다.
4. 마이크 사용을 허용한다. 미리보기·공유 오디오 상태 안내·ICE 연결을 확인한다.
5. 시청 창에서 영상 변화와 탭 소리, 직접 말한 마이크 음성을 각각 확인한다. 한 음원만 들리면 통과가 아니다.
6. `송출 정지`를 누르고 공유·마이크 사용 표시가 해제되는지 확인한다.
7. 다시 시작한 뒤 Chrome의 `공유 중지`로 종료한다. 마이크와 서버 송출도 함께 정리돼야 한다.
8. 별도 시도로 마이크 거부·화면 선택 취소를 검사한다. 실패 안내가 나오고 획득한 자원이 남지 않아야 한다.

같은 PC의 두 창은 예비 검사다. 요구사항의 **다른 기기 시청** 완료 증거가 아니다. 수신에 문제가 있으면 단순 연결 상태 외에 브라우저/OS, 화면 로그, 영상·음성 중 실패한 항목을 기록한다.

## 3. 휴대폰과 다른 기기 — 접근 환경 준비 후

현재 loopback 화면은 휴대폰에서 접속할 수 없다. 휴대폰의 localhost/127.0.0.1은 휴대폰 자신이다. 단순 HTTP LAN 주소는 카메라·마이크의 secure context 조건을 충족하지 못할 수 있다.

인증을 갖춘 HTTPS 검증 환경이 준비된 다음 실제 휴대폰에서 `모바일: 카메라+마이크`를 선택한다. 카메라와 마이크를 허용하고, 별도 물리 기기에서 영상·목소리를 확인한 뒤 휴대폰에서 종료한다. Wi-Fi/이동통신망, 브라우저·OS, 실행 시각을 기록한다. 화면 잠금·백그라운드 송출 지속은 지원으로 가정하지 않는다.

## 자동 회귀 검사와 정리

수동 송출을 종료한 뒤, 로컬 CPU 스택에서 실행한다.

```sh
npm ci
npm run verify
./stop.sh
```

자동 검사는 canvas·oscillator와 가짜 장치를 사용한다. 실제 PC 두 음원 청취·모바일 카메라·외부망 인수 검사를 대신하지 않는다. 결과 기록에는 합성/모의와 실제 기기를 명시한다.
