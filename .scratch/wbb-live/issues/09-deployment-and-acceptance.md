# 09: 공개 서비스와 평가 재현 완성

**What to build:** 평가자가 공개 URL과 README를 따라 로그인·PC/모바일 송출·다른 기기 시청·종료를 재현하고 운영자는 검증된 용량과 복구 방법을 확인한다.

**Blocked by:** 05 모바일·ABR, 06 Google 로그인, 07 복구·이벤트, 08 관측성.

**Status:** ready-for-agent

**실행 가능 여부:** 선행 미완료로 blocked. 저장소 생성·초기 코드 공개 자체는 이 티켓 완료와 별개다.

- [ ] 기존 서비스 유지 상태에서 WBB 전용 k3s 자원·볼륨·GPU 접근·Caddy·DNS only subdomain을 검증한다.
- [ ] HTTPS와 외부 이동통신망 ICE/필요 TURN을 확인하고 관리 API/DB/Redis/Kafka/OTLP/Grafana가 공개되지 않는다.
- [ ] 실제 업로드와1→2→4→가능한 경우10회차 단계 부하를 측정하고30분 이상 열·GPU·RAM·디스크·오류를 기록한다.500시청자 목표 미달도 그대로 보고한다.
- [ ] 측정에 맞춘 MAX_ACTIVE_BROADCASTS와 과부하 안내를 적용한다. 검증 전 운영 기본1개를 사용한다.
- [ ] 모든 필수 인수 항목을 실제 기기 결과와 자동 검사로 구분하여 통과/실패/미검증으로 기록한다.
- [ ] README에 서비스 URL·평가 로그인·환경변수 예시·실행·PC/모바일 송출/시청/종료·지원표·백업복원·OSS 출처·알려진 제약을 적는다.
- [ ] 공개 저장소 secret/개인 로컬 경로 검사, clean checkout 빌드와 실제 평가 로그인을 확인한다.

**검증:** 전체 필수 요구사항과 제출 체크리스트. 실제 기기/외부 자격 부재로 실행 불가라면 완료로 표시하지 않는다. 공개 저장소 게시 승인과 외부 서비스의 유료 생성 승인을 혼동하지 않는다.
