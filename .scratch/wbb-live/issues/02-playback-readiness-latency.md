# 02 후속: 재생 준비 상태와 라이브 지연

Status: in-review
기준:6cb0b2a, work/media-device-acceptance. 사용자 요청은 변환 영상 준비 전 재생 비활성화와 큰 지연 개선이다. 구현은 지정 대체 Codex, 조정자는 리뷰/검증.

## 계약
- 송출하지 않는 별도 시청 탭에서도 실제 HLS 준비를 판별한다. master200만으로 준비 완료를 주장하지 말고 재생 가능한 media playlist/초기 미디어 준비를 확인한다. 시작 전/변환 중 재생 disabled와 명확한 준비 상태, 준비 후 활성화.
- 느린 응답, 404/종료/재시작, 네트워크 오류, 이전 폴링 늦은 응답을 처리한다. 요청 timeout/중복 방지/pagehide정리를 갖추고 인증401/403과준비중404를구분한다. HTTPS 동일출처와기존localhost/native경로유지.
- HLS live edge와재생위치 차이를관측하고, startup과steady-state지연을구분한다. 기존사용자송출을중단하거나장치캡처하지않고baseline측정. 근거있는버퍼/live sync/encoder개선만 적용하며end-to-end와player-edge지표를혼동하지않는다.
- 사용자일시정지를임의해제하지않는다. 재생재시도/fatal오류복구에서죽은hls인스턴스재사용하지않는다. 방송종료와재시작의오래된재생/준비표시를회귀검사한다.
- 실제HTTP/Chrome사용자동작 경계로 준비전→준비후→종료→재시작검사. 변경전실패와변경후통과, 재생시간/프레임/오디오/지연측정 보고. 실제아이폰/외부망은보류.
- helper8090이embed코드를사용하므로수정코드의실제서빙반영도검증. 원래송출중인서비스재시작은조정자와협의하고현재송출보존. 서비스정리/커밋/푸시는조정자담당.

## 체크포인트

준비 상태·버튼 제어·오류 복구·명시적 라이브 이동을 로컬8090에 반영했다. 독립 CPU83, fixture11, HTTP16, HTTPS미디어14, 별도 송출/시청12 검사를 통과했다. 두 축 리뷰 잔여 확정 결함0건이다. 실제 사용자 캡처 지연 재시험은 남아 있으며 합성 측정으로 완료 처리하지 않는다.
