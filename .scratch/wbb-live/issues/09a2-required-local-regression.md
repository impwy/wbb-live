# 09-A2: 최종 제품 로컬 필수 기능 회귀

**Status:** ready-for-agent
**Blocked by:** 09-A1 평가 로그인 구현·독립 검증. 07-A2 신규 미디어 작업 종료 계약은 로컬 검증 완료.
**목표:** 최종 제품의 인증·방송 CRUD·권한·PC/카메라 송출·익명 시청·종료·영속성을 한 버전의 새 전용 스택에서 공개 API와 Flutter 화면으로 재현한다.

## 범위

1. 기존 07-A2 검증 자원과 helper8090을 보존하고, 별도 이름·포트·PostgreSQL DB·Redis·MediaMTX 이력 볼륨·root/slot/key·Flutter 빌드로 clean bootstrap한다. 이력 볼륨 bootstrap은 처음 만든 빈 전용 볼륨에 명시적으로 한 번만 한다. 로컬 테스트 인증서와 공개 신뢰 TLS를 구분한다.
2. 공개 HTTP API+실제 PostgreSQL에서 A(방송자), B(다른 사용자), 익명 시청자로 가입·로그인·refresh·로그아웃, 방송 등록/목록/상세/수정/삭제, 활성 중 삭제 거절, 방송 소유자/타 사용자/익명 허용·거절을 검사한다. API와 PostgreSQL을 볼륨 유지 상태로 재시작하고 ID·소유자·제목·설명·종료 회차를 다시 읽는다.
3. 최종 Flutter 화면의 평가 로그인→방송 등록→시작→시청→종료→로그아웃, PC 화면·공유 소리+마이크와 카메라·마이크를 각각 실제 브라우저 미디어 경계에서 검사한다. 자동화의 합성 장치는 실제 PC 화면·휴대폰 기기 인수라고 기록하지 않는다. 송출과 시청은 다른 Chrome 프로세스로 실행하고 H264 프레임·서로 구분되는 음원·종료 뒤 HLS/WHIP 차단과 FFmpeg/ingress 부재를 관측한다.
4. 실패·경합 최소 회귀는 공유 중지, 카메라 권한 거절, 중복 시작·종료, 다른 사용자 송출 제어, 늦은 publish 응답, 서버 재시작과 완료 근거를 포함한다. 기존 각 티켓의 검증기를 재사용하고 새 스크립트는 빠진 공개 경계만 보완한다.
5. README에는 clean checkout 실행·환경변수 자리표시자, PC·모바일 브라우저 조작 절차, 현재 실제 검증 범위와 남은 물리 기기 관문을 명시한다. 결과를 `docs/verification/09a-official-required-acceptance.md`에 코드 해시·이미지 digest·명령·종료 코드·상태로 기록한다.

## 완료 기준

- 새 전용 스택이 누락·부분 설정을 거절하고, 준비 이후 공개 API/Flutter/미디어 검사를 통과한다. 테스트 종료 후 활성 회차·미완료 작업·FFmpeg·ingress가 0이며 일회용 자원만 정리한다.
- 실제 DB/API 재시작 후 방송 정보와 종료 상태가 유지되고, 로그인 상태·권한이 예상대로 동작한다. 별도 공개 HTTPS 배포와 실제 PC 캡처/물리 iPhone·외부망 검사는 09-A3의 미완료 관문으로 남긴다.
- 전체 Go race·vet, Flutter analyze·관련 테스트·release build, 공개 브라우저 검증의 결과를 분리해 기록한다. 제품 구현 담당은 변경·검사·자원을 보고하고 동결한 뒤 조정자 독립 검증을 받는다.
