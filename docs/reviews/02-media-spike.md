# 02 단일 품질 미디어 검증 리뷰

범위: `experiments/media-single-rendition/`. 제품 Flutter/API에 연결하기 전 로컬 전용 기술 검증이다. 구현은 지정 pi GLM, 검토는 Codex와 독립 리뷰 에이전트가 수행한다.

## 첫 검토에서 발견한 문제

1. 화면 공유 트랙의 `ended`가 공통 종료로 연결되지 않아 마이크·WHIP 세션이 남았다.
2. 캡처 권한·WHIP 응답을 기다리는 동안 종료하면 늦은 응답이 송출을 다시 시작하거나 이미 정리한 PeerConnection에 접근했다. SDP 처리 실패도 정리가 보장되지 않았다.
3. 마이크 거부를 삼키고 화면 공유를 계속했다. 필수 음원이 없는 실패는 획득한 트랙까지 정리해야 한다.
4. FFmpeg 필터가 너비만 제한해 세로 입력의 높이가 720을 초과했다.
5. 검증기가 출력 치수를 엄격히 파싱하지 않고 미확인 값도 통과시켰다. 연결·manifest 성공만으로 실제 시청을 입증하지 못했다.
6. 종료 스크립트의 광범위한 `pkill`과 미확인 PID, HTTP 서버의 외부 바인딩 허용, 모든 Origin 허용은 로컬 실험의 격리 범위와 맞지 않았다.

pi가 시도별 자원 소유권, 늦은 POST 정리, 양축 해상도 제한, loopback 강제, 소유 프로세스 확인을 반영했다. 최종 검증 중 GLM 제공자가 5시간 한도 `429/1308`을 반환해 추가 수정이 중단됐다. 아래는 수정 전 체크포인트의 남은 결함이며 승인·완료 보고가 아니다.

## Standards

고정 기준 `87b6aee`, 검토 스냅샷 `83dcc6d`의 실험 코드에 대한 독립 검토다. 아래 줄 번호는 해당 스냅샷 기준이다.

- **P1, 문서 기준 위반:** `web/app.js:320–330`에서 화면 획득 후 마이크 권한을 기다리는 동안 영상 `ended`를 처리하지 않는다. 공유 중지 후 마이크 허용 시 종료된 영상과 살아 있는 마이크로 시작을 계속한다. `docs/design.md`의 공유 중지 정리 계약 위반이다. 원본 트랙 획득 즉시 종료 처리기를 연결하고 await 후 readyState도 확인해야 한다. Node VM 모의 재현에서 대기 중 리스너0개, 반환 영상 ended·오디오 live를 확인했다. 실제 장치 검증은 아니다.
- **P2, 문서 기준 위반:** `web/app.js:297–308`의 합성 초기화는 모든 오디오 노드 생성이 성공한 뒤에만 정리를 등록한다. 중간 예외 시 canvas track·RAF·AudioContext가 남는다. 자원 획득 직후 각각 정리를 등록해야 한다.
- **P2, 검증 결함:** `verify.sh:15–21`은 master에서 media playlist 전용 `EXT-X-PART-INF`를 찾는다. 리다이렉트를 따라가고 variant URI를 해석한 뒤 media playlist를 검사해야 한다. 스타일 문제가 아닌 실행 오류다.

Standards 3건, 최고 심각도 P1(공유 중지 경합). 별도로 보고할 코드 냄새는 없었다.

## Spec

- **P2:** `web/app.js:330` 마이크 대기 중 공유 중지를 놓친다. 명세의 “화면 공유 track의 ended는 사용자 종료와 같은 경로”를 충족하지 않는다. 획득 즉시 리스너 연결 및 마이크 응답 후 영상 상태 확인이 필요하다.
- **P2:** `web/app.js:349–351`은 공유 오디오와 마이크를 gain 없이 destination에 직접 합산한다. 명세의 clipping 방지 gain이 빠졌다. PC 혼합 경로의 감쇠와 두 입력 동시 피크를 검사해야 한다. 합성 oscillator의 gain은 PC 경로 검증을 대신하지 않는다.
- **P2:** `verify.sh:15–21`의 master 태그 검사는 “실측 codec/manifest를 사용한다”는 티켓 계약에 맞는 검증이 아니다. 올바른 media playlist를 따라가야 한다.

Spec 3건, 최고 심각도 P2. 범위 확장은 발견하지 않았고 실제 장치·외부망·VAAPI는 계획대로 미검증이다.

## Codex 독립 재생 진단

- 기본 Playwright Chromium141은 H.264 `canPlayType`이 빈 문자열이며 hls.js에서 `manifestIncompatibleCodecsError`가 발생했다. 설치된 Chrome156은 H.264/AAC에 `probably`를 반환한다. 검증 실행기는 Chrome 선택과 코덱 사전 검사가 필요하다.
- Chrome156에서 현재 native HLS 우선 분기는 `NotSupportedError`, readyState0·프레임0으로 실패한다. hls.js/MSE로 진단용 경로를 강제하면1280×720 재생이 진행된다. Chrome은 MSE 경로를 사용하고 native 실패 시 fallback 및 정확한 오류 안내를 구현해야 한다. 모든 재생 오류를 자동재생 정책으로 표시하지 않는다.
- 실제 코드 전체 검사는50통과·1건 건너뜀·2실패다. 두 실패는 재생 시간과 디코딩 프레임 증가다. 진단용 강제 경로의 성공을 현재 코드 통과로 계산하지 않는다.
- 서버의 source/WHIP 세션 소멸은 검사했지만 FFmpeg 원래 PID 종료·출력 연결 소멸과 새 part 생성 중단은 아직 완료 증거가 없다. 종료 검사에 추가해야 한다.

## 완료 판단의 경계

로컬 합성 입력의 성공은 실제 PC 공유 오디오·마이크, 휴대폰 카메라, 다른 기기 시청, 외부망 ICE, Safari HTTPS, VAAPI 및 ABR의 성공을 의미하지 않는다. 티켓 02는 해당 실측이 없는 동안 완료로 처리하지 않는다.
