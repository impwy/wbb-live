# 09-A3: 공개 HTTPS 배포와 두 기기 필수 기능 인수

**Status:** needs-info (공개 ICE 경로·실제 iPhone 관측 환경)
**Blocked by:** 09-A2 최종 로컬 필수 기능 회귀. Labtop의 외부 ICE 포트 전달과 실제 iPhone Chrome·별도 시청 기기 인수가 필요하다.
**목표:** 최종 제품을 `https://live.wombatburrow.com`에서 접속 가능하게 배포하고 심사자가 README만으로 PC·모바일 필수 시나리오를 재현하게 한다.

## 배포 설계·준비

우선 배치 후보는 **WBB 전용 단일 노드 k3d/k3s 클러스터**다. 기존 syong 클러스터의 포트 매핑은 WBB HTTP·ICE를 노출하지 않으므로 그 namespace만 추가해 공개 인수를 주장하지 않는다. 전용 클러스터의 HTTP ingress는 기존 호스트 네트워크 Caddy가 loopback 전용 포트로 프록시하고, MediaMTX는 노드 고정 및 별도 UDP 매핑을 시험한다. k3d UDP 매핑→Pod hostNetwork→브라우저 ICE의 실제 통과는 설계 가정이며 로컬·외부 spike 전에는 확정하지 않는다. 외부 라우터 전달이 불가능하면 지원되는 공개 송출 경로를 다른 방법으로 입증하기 전까지 이 티켓은 미완료다.

1. `Labtop`의 기존 Caddy·사이트·데이터와 k3s 계열 클러스터를 읽기 전용으로 조사하고 리소스·포트·네트워크를 기록한다. 관측 시점에는 기존 Caddy가 호스트 네트워크에서 실행되고 k3d의 k3s 클러스터가 있으며, 공개 live TLS는 실패한다. 루트 볼륨 여유가 약 16GiB이므로 이미지 빌드·PVC 용량을 먼저 계산하고 기존 이미지·볼륨을 일괄 정리하지 않는다. 이 사실을 공개 연결 성공으로 바꾸어 기록하지 않는다.
2. WBB 전용 namespace, PostgreSQL·Redis·Kafka 데이터/Secret, API·worker·고정 패치 MediaMTX·Flutter 정적 서비스의 이미지와 설정을 commit/digest에 고정한다. 완료 계약의 root·slot·key·anchor와 이력 PVC는 모든 컴포넌트에 정확히 일치시키고 최초 빈 PVC에 운영자가 명시적으로 한 번만 bootstrap한다. 기존 WBB 실험 이력과 다른 서비스 볼륨을 재사용하거나 지우지 않는다. 현재 클러스터의 기본 `local-path` StorageClass는 reclaim policy가 `Delete`이므로 사용자 DB·완료 이력 PVC에 기본 삭제 정책을 그대로 적용하지 않는다. GPU·CPU 인코더는 실제 노드 검증 결과대로 명시하고 자동 전환하지 않는다.
3. Caddy에는 live 호스트의 독립 route만 추가하고 전체 설정을 보호 사본에서 validate한 뒤 최신 운영 설정의 해시를 재확인해 적용한다. 기존 사이트·인증서·allowlist는 유지한다. 공개 경로는 UI/API/인가된 HLS/WHIP만 허용하고 DB·Redis·Kafka·관리 API·Grafana는 외부에 열지 않는다. 브라우저 ICE UDP/TCP의 실제 공인망 전달 경로를 확인한다.
4. 평가용 전용 계정은 운영 DB에 먼저 생성하고 비추적 Secret으로만 평가 로그인 설정을 주입한다. 공유 계정의 방송·동시 회차 자원 상한, 세션 리셋·테스트 방송 정리 절차와 관측 수단을 공개 전 검증한다. Caddy 뒤의 현 `RemoteAddr` 제한은 클라이언트별 제한이 아니므로 실제 프록시 경계에 맞는 신뢰 모델 없이는 IP별 보호라고 주장하지 않는다.
5. 배포 전후 기존 호스트의 핵심 응답·컨테이너 신원·포트·볼륨을 비교한다. 실패 시 live 전용 route와 WBB 전용 서비스만 되돌리고 기존 트리를 과거 백업으로 덮지 않는다. 사용자 자료 PVC와 종료 이력은 롤백에도 보존한다.

## 공개 인수

- 다른 회선에서 신뢰 TLS의 live URL에 익명 목록·상세·재생, 평가 로그인·로그아웃이 실제로 작동한다. API의 Origin·소유자·타 사용자·익명 권한과 저장/재시작 영속성을 다시 확인한다.
- 실제 PC Chrome/Edge 화면 공유의 화면 변화, 탭/시스템 소리+마이크를 별도 물리 기기에서 구분해 보고 듣는다. 시작·브라우저 공유 중지·종료 후 캡처·WebRTC·HLS·FFmpeg/ingress 정리를 확인한다.
- 실제 iPhone Chrome 카메라+마이크 송출을 별도 PC에서 시청하고 영상·음성·종료를 확인한다. Wi-Fi와 모바일 회선을 구분하고 외부망에서는 HTTPS 성공과 ICE/RTP/HLS 데이터 흐름을 각각 기록한다. 실제 조작·권한·기기 정보가 없으면 통과로 표시하지 않는다.
- README에 실제 동작하는 URL, 평가 로그인 절차, 지원 기기·브라우저, 환경변수 자리표시자, clean checkout 실행, PC·모바일 시연 절차를 최종 관측값으로 갱신한다. 공개 저장소와 CI, 오픈소스 출처·비밀 누출 검사를 마친다.

배포 설정 작성·정적 검증과 실제 외부 인수는 별도 단계다. 최종 물리 기기·외부망 조건이 충족되지 않으면 상태를 `done`으로 올리지 않는다.
