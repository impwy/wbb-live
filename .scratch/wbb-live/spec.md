# WBB Live 명세

**Status:** ready-for-agent

**구현 상태:** 미구현 기준 명세. 티켓별 검증과 Codex 리뷰가 끝나기 전 완료로 간주하지 않는다.

## Problem Statement

방송자가 PC 화면과 공유 오디오·마이크 또는 휴대폰 카메라·마이크를 실시간으로 송출하고, 로그인하지 않은 다른 기기의 시청자가 웹에서 볼 수 있어야 한다. 방송자는 자신의 방송 정보와 송출만 제어할 수 있어야 하며, 종료 이후 실제 송출이 중단되고 서버 재시작 후에도 방송 정보가 남아야 한다. 공모 평가자가 공개 서비스와 실행 문서로 필수 기능을 재현할 수 있어야 한다.

## Solution

Go API와 Flutter Web으로 방송 목록·시청·방송 관리·송출 스튜디오·인증 화면을 제공한다. MediaMTX에 WebRTC/WHIP로 송출하고 FFmpeg GPU 변환 후 LL-HLS로 시청한다. 같은 출처의 Caddy와 `live.wombatburrow.com`을 사용하며 CDN 없이 Labtop에서 운영한다. 먼저 이메일 인증과 방송 CRUD의 완전한 사용자 흐름을 만들고, 실제 미디어 단일 품질 검증 → 송출 통합 → 모바일·ABR → 복구·운영 검증으로 진행한다.

2026-11-09 사용자 승인: 실제 휴대폰·외부망 인수는 미완료로 유지하고04 로컬 단일 품질 통합을 먼저 구현한다. 세부 범위와 검증은04 및 하위 티켓을 따른다.

필수 기능 전체 진행 목표의 상태 근거는 `docs/verification/required-implementation-status.md`에서 관리한다. 단일 품질 모바일은05-A로 분리하고04-B 이후 진행하되, 기존05의 ABR와 실제 기기 인수는 유지한다.

## User Stories

1. 방문자로서 로그인 없이 방송 목록과 제목·상태를 보고 시청할 방송을 고르고 싶다.
2. 방문자로서 PC나 휴대폰에서 선택한 라이브의 영상과 음성을 재생하고 싶다.
3. 시청자로서 자동재생이 막히면 재생/소리 켜기 버튼으로 시작하고 싶다.
4. 시청자로서 준비 중·방송 중·종료 상태를 구분하고 종료된 방송을 계속 연결 중으로 보지 않고 싶다.
5. 사용자로서 이메일·비밀번호로 가입하고 로그인·로그아웃하고 싶다.
6. 사용자로서 Google 계정으로 안전하게 로그인하고 싶다.
7. 사용자로서 페이지를 새로 열어도 유효한 로그인 상태를 복원하고 만료되면 안내받고 싶다.
8. 사용자로서 로그아웃 후 이전 인증 정보로 내 계정이 사용되지 않기를 바란다.
9. 방송자로서 제목·설명을 등록하고 내가 소유한 방송을 조회·수정·삭제하고 싶다.
10. 방송자로서 다른 사람이 내 방송 정보를 바꾸거나 방송을 시작·종료하지 못하게 하고 싶다.
11. 방송자로서 PC의 화면/탭과 공유 소리·마이크를 함께 송출하고 싶다.
12. 방송자로서 공유 소리가 빠졌거나 권한이 거절되면 원인과 재선택 방법을 알고 싶다.
13. 방송자로서 휴대폰 카메라·마이크로 방송을 시작하고 다른 기기에서 시청되는지 확인하고 싶다.
14. 방송자로서 실제 영상이 준비된 이후 방송 중 표시를 보고 싶다.
15. 방송자로서 시작 버튼을 두 번 눌러도 중복 송출 회차나 변환 프로세스가 생기지 않기를 바란다.
16. 방송자로서 종료 버튼·화면 공유 중지·로그아웃 시 송출과 장치 사용이 멈추기를 바란다.
17. 방송자로서 네트워크 단절·탭 종료 후 서버가 유령 방송을 계속 표시하지 않기를 바란다.
18. 방송자로서 종료된 방송을 다시 시작할 때 과거 연결이나 이벤트가 새 회차를 방해하지 않기를 바란다.
19. 방송자로서 다른 사용자가 내 송출 권한이나 종료된 회차의 권한으로 재접속하지 못하게 하고 싶다.
20. 사용자로서 서버 재시작 후에도 등록한 방송 정보와 소유권을 조회하고 싶다.
21. 시청자로서 검증된 영상 품질을 선택하거나 네트워크 상태에 따라 자동 품질로 시청하고 싶다.
22. 운영자로서 API·방송·미디어·인프라의 지연과 실패를 한곳에서 확인하고 싶다.
23. 운영자로서 관측 저장소나 Kafka가 잠시 멈춰도 로그인과 송출 종료가 막히지 않기를 바란다.
24. 운영자로서 과부하 전에 입장을 제한하고 실제 검증된 용량을 공개하고 싶다.
25. 평가자로서 공개 서비스 URL과 평가 로그인 방법을 이용해 PC·모바일의 시작·시청·종료를 재현하고 싶다.
26. 개발자로서 공개 저장소에서 비밀 없이 실행 환경·설정 예시·테스트 결과·제약·오픈소스 출처를 확인하고 싶다.

## Implementation Decisions

- 프런트엔드는 Flutter Web, 백엔드는 Go 모듈형 모놀리스와 worker다. PostgreSQL은 원장, Redis는 제한·캐시, Kafka는 outbox 기반 비동기 이벤트이며 각각 WBB 전용이다.
- 방송 정보와 송출 회차를 분리한다. 방송별 활성 회차는 하나다. 회차 상태는 STARTING→LIVE→STOPPING→ENDED이며 재시작은 새 회차다. READY는 회차 없는 방송의 표시 상태다.
- 인증은 단기 access JWT, 서버 인증 세션, 회전 HttpOnly refresh cookie다. Google은 OIDC Code+PKCE이며 이메일만으로 계정을 자동 연결하지 않는다.
- 서버가 소유자를 결정하고 모든 보호된 동작에서 인증 세션·DB 소유권·현재 상태를 확인한다. UI 숨김만으로 권한을 구현하지 않는다.
- 시작/종료와 이벤트는 멱등이고 늦은 과거 회차 이벤트를 무시한다. 종료는 권한 차단·실제 ingress 종료·FFmpeg 종료 확인까지 포함한다.
- PC는 Web Audio로 공유 오디오와 마이크를 합성한다. 모바일은 카메라·마이크를 사용한다. 브라우저별 실제 지원 범위를 기록한다.
- MediaMTX WHIP 입력과 FFmpeg Intel VAAPI 변환, LL-HLS 출력을 사용한다. 먼저 단일 품질을 확인하고1080/720/480 ABR 정렬·전환을 별도 검증한다. 독립 출력 경로를 master로 묶는 것만으로 ABR 완료를 주장하지 않는다.
- Caddy 같은 출처와 기존 도메인의 live 서브도메인을 사용한다. CDN은 사용하지 않고 기존 서비스는 유지한다. WebRTC 네트워크 경로는 HTTPS와 별도 검증한다.
- OTel은 계측, Alloy는 수집, 전용 Loki/Grafana/Tempo/Mimir는 저장·조회다. bounded queue, 최소 retention, 비밀 제거와 관리망 접근을 적용한다.
- 동시10방송/500시청자는 측정 목표다. 실제 자원과 외부망 성능으로 입장 제한을 정하며 보장으로 표현하지 않는다.

## Testing Decisions

- 공개 HTTP API에서 가입·로그인·로그아웃·권한·버전 충돌·상태 전이를 검사한다. 내부 함수 호출 횟수보다 외부 결과를 확인한다.
- 실제 PostgreSQL로 마이그레이션·동시성·refresh 회전·outbox 멱등·재시작 영속성을 검사한다. 모의 저장소 테스트만으로 영속성을 통과시키지 않는다.
- Flutter 사용자 동작 경계에서 인증·목록·CRUD·송출 상태·오류 안내를 검사하고 web build/analyze를 실행한다.
- 실제 두 기기로 PC 두 음원, 모바일 카메라·마이크, 외부망, 종료, 미디어 재접속 거절, ABR 전환을 검사한다. 모의 미디어 자동 테스트는 별도 근거이며 이를 대체하지 않는다.
- 기존 구현이 없는 신규 프로젝트이므로 선례 테스트는 없다. 첫 티켓에서 API·DB·UI 검증 경계를 만든다.
- 부하·장애 검사는 단계적으로 실행하고 기존 서비스에 영향을 주기 전에 중단한다. 실제 실행 결과와 실행 불가 사유를 티켓에 기록한다.

## Out of Scope

댓글·채팅·도네이션·결제·녹화·다시보기, 네이티브 앱, 추천·구독, CDN, 다중 지역, 무조건적인10/500 용량 보장, 검증하지 않은 모든 브라우저 지원, 외부 알림 발송.

## Further Notes

설계·리뷰·검증은 이 대화의 Codex가 맡는다. 구현 담당은 AGENTS.md와 docs/agents/implementation-handoff.md를 따른다. 기본 pi GLM이 한도·오류로 중단되면 사용자 승인 대체 Codex가 구현하고, 복구 후 pi로 인계한다. 사용자는 개발·서브에이전트 활용·공개 `wbb-live` 저장소 게시를 승인했다. 역할이나 구현 모델을 임의로 바꾸지 않는다. 문서상의 완료 기준은 구현 증거가 아니며 실제 결과가 기록될 때까지 미완료다. 외부 OAuth 설정, 실제 기기, 도메인·인증서, Wi-Fi 업로드, ABR 정렬은 각각 검증 관문이다.
