# 02 실제 기기·외부망 적용 및 인수 계획

2026-11-09 사용자가 휴대폰 연결과 외부망 검증 진행을 요청했다. 대상 기기는 아이폰 Google Chrome이다. 현재 문서는 적용 전 계획이며 실제 성공 기록은 `02-device-acceptance.md`에 남긴다.

## 적용 범위

- 기존 Caddy의 conf.d import에 live.wombatburrow.com 전용 host를 추가한다. 기존 사이트별 cloudflare_only snippet과 자동 생성 allowlist는 유지한다. root·www DNS와 기존 인증서는 변경하지 않는다.
- live는 origin을 직접 가리키는 DNS only 레코드가 필요하다. proxied apex를 CNAME으로 참조하면 CDN 미사용 기준을 충족하지 못하므로 live 전용 A 레코드를 우선한다. 실제 origin 주소는 비공개 설정에서만 관리한다.
- 정적 검증 화면은 기존 Caddy bind 안의 독립 디렉터리, WHIP/HLS는 서버 loopback19889/19888, ICE/TCP는 명시 서버 인터페이스18391만 사용한다. 별도 wbb-media-acceptance 프로젝트를 사용한다.
- 공개 TLS는 live 이름의 신뢰 인증서를 사용한다. 실험용 internal CA와 인증서 경고 우회는 실제 기기 인수에 사용하지 않는다.
- 임시 Basic Auth 비밀번호는 비공개로 생성·전달하고 해시만 보호된 설정에 렌더링한다. 운영 Caddy 컨테이너 재생성 없이 전체 설정 validate 후 reload한다. 제품 로그인·권한 검증과 구분한다.

## 적용 전 조건

1. 최종 코드 리뷰 수정과 독립 Chrome/Caddy 검증을 통과한다. 실제 기기 관문은 자동검사로 대신하지 않는다.
2. live DNS가 origin 직접 주소를 반환하는지 확인한다. 실제 Cloudflare 레코드 정보와 변경 수단은 확인 중이다.
3. 서버의 비공개 bind 경로·기존 파일 목록/해시와 내용을 보호된 staging에 복사한다. 현재 운영 이미지 ID의 일회성 컨테이너에 전체 사본을 `/etc/caddy:ro`로 마운트하고 포트를 공개하지 않은 채 adapt/validate한다. 절대 import가 운영 트리로 빠지지 않도록 동일 마운트 위치를 사용한다. JSON·자격 렌더링 파일은0600으로 보호하고 출력하지 않는다. 적용 직전 기존 파일 변경 여부를 재확인하고 변경됐다면 최신 사본으로 다시 검사한다.
4. 선택한 포트 충돌이 없는지 다시 검사한다. 기존 서비스 컨테이너 목록/식별자를 보존한다.
5. 공유기의 TCP18391 포트 전달과 서버 방화벽 허용을 확인한다. UFW는 현재 비대화형 sudo 조회 권한이 없어 미확인이다. broad ACL 해제 대신 필요 경로만 사용자 관리 수단으로 확인한다.

## 실제 적용과 점검

1. 검토한 코드와 설정을 서버 독립 디렉터리에 배치한다. 비밀은 저장소 밖에서 권한을 제한한다.
2. CPU/VAAPI 중 명시한 인코더로 전용 미디어 프로젝트를 시작한다. 실패 시 자동 인코더 대체하지 않는다. HTTP 관리 포트는 외부에 노출하지 않는다.
3. 전체 Caddy 설정을 검증하고 기존 Caddy만 reload한다. 기존 사이트의 응답과 컨테이너 식별자가 보존되는지 확인한다.
4. 공개 인증서·UI/HLS/WHIP 미인증401·잘못된 Origin403·정상 Origin 도달성을 검사한다. 토큰/SDP/실제 자격은 로그에 남기지 않는다.
5. Wi-Fi에서 PC 화면+탭 소리+마이크→아이폰 시청, 아이폰 카메라+마이크→PC 시청을 확인한다. 각 단계에서 종료·장치 해제도 확인한다.
6. 아이폰 Wi-Fi를 끄고 LTE/5G로 반복한다. 신호 HTTPS 성공과 ICE 연결 성공을 별개로 기록한다. 외부 ICE가 실패하면 후보·포트/NAT 원인을 진단한 뒤 TURN 필요성을 결정한다.
7. OS/브라우저 버전·시각·망·영상·두 음원·권한 거부·종료 결과를 기록한다. iOS Chrome 성공을 Safari 성공으로 전환해서 기록하지 않는다.

## 롤백

이번 live 추가 파일만 import 범위 밖으로 옮기거나 그 파일의 직전 버전으로 복원한 뒤 전체 설정을 validate/reload한다. 기존 전체 트리를 과거 백업으로 덮어써 동시 갱신된 allowlist를 되돌리지 않는다. 기존 host 설정·allowlist를 유지한다. 전용 미디어 프로젝트와 그 port mapping만 종료한다. live DNS를 변경했다면 기록한 직전값으로 복원한다. 기존 사이트와 서비스가 유지되는지 재검사한 뒤 독립 정적 파일을 정리한다.

## 현재 확인한 사실

- Mac에서 origin TCP80/443 연결 성공, live SNI TLS는 실패했다. 이는 이동통신망 성공을 의미하지 않는다.
- Caddy에는 conf.d import가 이미 있으며 새 독립 파일을 추가할 수 있다. 기존 cloudflare_only는 각 host가 import하는 snippet이다.
- 19888/19889/18391 리스너는 관측 시점에 없었다. 실제 적용 직전에 재확인한다.
- DNS는 Cloudflare 주소, 공개 HTTPS는525였다. DNS·공개 인증서·ICE가 준비되기 전 사용자에게 접속 성공을 안내하지 않는다.
