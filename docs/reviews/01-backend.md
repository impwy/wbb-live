# 01 백엔드 중간 리뷰

작성: 2026-11-06. 대상: `d16c46f..59cd0f9`. 단계1의 Go API와 로컬 실행 구성을 두 독립 Codex 에이전트가 검토했다. 제품 구현과 수정은 지정 pi의 GLM이 담당한다. Flutter와 후속 라이브 기능은 이 리뷰 범위가 아니다.

## Standards

명시 기준 위반 2건, 냄새 휴리스틱 지적 0건.

1. **P2 — 계정별 인증 제한 누락.** 설계 §4는 IP와 계정 제한을 모두 요구하나 현재 제한 키는 요청 종류·IP만 포함한다. 여러 IP의 동일 계정 요청을 함께 제한해야 한다.
2. **P2 — 기본 실행의 Origin 누락.** `make run-backend`는 허용 Origin을 제공하지 않아 별도 export 없이 실행하면 인증 POST가 403이다. 기본 개발 실행이 필요한 설정을 제공해야 한다.

Standards 총 2건. 이 축에서 가장 중요한 문제는 계정별 인증 제한 누락이다.

## Spec

명세 지적 5건. 범위 확장은 발견하지 않았다.

1. **P2 — Redis 캐시 유실 후 인증 복구 불가.** 키가 없으면 유효한 PostgreSQL 세션도 401로 처리된다. Redis가 정상인 cache miss는 DB 원장으로 복구하고 실제 Redis 장애는 503으로 거절해야 한다.
2. **P2 — 계정별 인증 제한 누락.** IP 제한만으로는 분산된 동일 계정 공격을 막지 못한다.
3. **P2 — 수정 시 제목·설명 한도 우회.** trim한 값을 검증한 뒤 원문을 저장한다. 직접 HTTP 검사에서 공백을 포함한 102자 제목이 저장됐다.
4. **P2 — 비밀번호 문자 수 불일치.** UTF-8 바이트 수 검사로 한글 4자 비밀번호가 가입을 통과했다. 계약은 12~128자다.
5. **P2 — 단건 방송 응답 형태 불일치.** 문서는 최상위 방송 객체, 코드는 `{broadcast: ...}`를 사용했다.

Spec 총 5건. 이 축에서 가장 중요한 문제는 Redis 캐시 유실로 정상 세션을 사용할 수 없게 되는 점이다.

## 처리와 검증

- 단건 응답의 `{broadcast: ...}` 형식은 인증의 `{user: ...}`와 일관된 계약으로 수용했다. 아직 외부 클라이언트가 없는 초기 단계이며 `docs/design.md`에 명시했다. DELETE의 version query와 외부 상태값 소문자 직렬화도 명확히 했다.
- 나머지는 pi가 수정하고 회귀 테스트를 추가했다. 재리뷰에서 발견한 캐시 복구와 회전의 경합은 family 행 잠금·원장 재검사로, refresh 제한 키의 회전 문제는 안정적인 사용자 ID로 해결했다. 최종 독립 재리뷰의 해당 범위 잔여 결함은0건이다.
- 사전 보안 리뷰에서 발견한 refresh 동시 재사용, Origin 검증, 잘못된 쿠키가 Bearer 로그아웃을 가리는 문제는 이 체크포인트에 수정돼 있다.
- Codex 독립 실행: `GOTOOLCHAIN=go1.27.3 go test -race -count=1 ./...` 통과. 실제 PostgreSQL과 테스트 전용 Redis를 사용했으며 HTTP 테스트 패키지는 약29초 소요됐다.
- 업데이트 후 `govulncheck` 결과: 호출 경로0건, import한 패키지0건. 미사용 `golang.org/x/crypto/openpgp` 모듈 경고 [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) 1건은 별도 기록한다. OpenPGP는 이 서비스가 사용하지 않는다.
- 최종 Codex 독립 실행: 백엔드30개 테스트(-race), vet, build 통과. HTTP 테스트 패키지 약42.5초. 실제 PostgreSQL 컨테이너 재생성과 API 프로세스 재시작 후 방송 정보가 보존됐고, 임시 서명 키 변경 뒤 브라우저가 refresh로 복구하는 것도 확인했다.
- 실제 PC/휴대폰 미디어와 운영 HTTPS 검사는 미완료다. API 테스트 통과가 라이브 서비스 완료를 뜻하지 않는다.

## 후속 수정: 테스트 자원 정리

2026-11-07 재개 점검에서 `TestMain`의 `defer stopRedis()`가 `os.Exit` 때문에 실행되지 않는 결함을 발견했다. 이전 검증에서 만들어진 임시 Redis17개를 식별해 제거했고, 별도 사용 중인 Redis는 유지했다.

pi는 준비·테스트·정리를 정상 반환하는 `runTests`로 옮기고 `TestMain`이 반환 코드만 전달하게 수정했다. 새 임시 컨테이너에는 `wbb.test` 라벨을 붙인다. Codex가 `TestBroadcastLifecycle` 성공과 PostgreSQL 연결을 의도적으로 실패시킨 경로를 검사했으며, 두 경우 모두 새로 남은 테스트 컨테이너는0개였다. 제품 인증·방송 동작에는 변경이 없다.
